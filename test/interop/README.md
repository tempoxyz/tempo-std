# Key authorization interoperability

From the repository root, with Foundry and the current stable Rust toolchain installed:

```sh
cargo run --locked --manifest-path test/interop/Cargo.toml
```

Set `FORGE` to an executable path if `forge` is not on `PATH`. This runs
`KeyAuthorizationInteropTest` and reads its JSON event output, then decodes the
fresh Solidity-generated bytes using the canonical `tempo-primitives` crate,
pinned to [07761a78](https://github.com/tempoxyz/tempo/commit/07761a78a4ac00988533aa8acbcb6667786b625d).
The lockfile pins transitive dependencies. No RPC or live wallet is used;
private keys 1 and 2 are public test fixtures.

The six fixtures cover no authorization, unrestricted access, empty spending
and call lists, populated limits/scopes with expiry and a zero witness,
account-bound admin authorization, and fee sponsorship. Each verifies:

- Fully consumed Rust decoding and byte-for-byte Rust re-encoding of both
  unsigned and signed transactions and the signed key authorization.
- All decoded transaction and authorization fields against independently
  constructed Rust values, including omitted versus empty optional fields.
- User, fee-payer, and authorization signing hashes.
- Recovery of the expected authorization signer, transaction signer, and sponsor.

The Solidity no-authorization fixture also locks all four transaction encoding
and hash paths to fixed vectors. `KeyAuthorizationValidationTest` covers malformed
RLP, invalid field shapes, contradictory restrictions, and direct struct mutation.
These are wire-format checks; they do not establish acceptance by a live node
with particular account state, balances, or hardfork rules.
